# 粗需求目标与范围拆解

面向产品线新需求与战略需求。保留原始目标和表述，不把它们误当已验证的用户痛点，也不撰写 PRD 或版本包。

明确提出方想达成的目标、目标用户和实际场景；区分事实、业务假设、方案偏好与待确认事项。将混合诉求拆成可单独评审的候选，标注 App、固件、硬件、设计及外部系统的可能依赖与边界。竞品具备某功能只能作为竞争线索，不能单凭这一点宣称需求已获市场验证。

每条候选保留对应原文引用、问题或机会陈述及缺失信息。原文没有指标、优先级、负责人或版本时留空待补，不得编造；证据不足时允许零候选。
