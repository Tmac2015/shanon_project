# 独立 Skill 试验台

在本目录运行 `python3 server.py`，访问 `http://127.0.0.1:8086`。无需启动旧平台、同步飞书或配置 VOC/BI 数据接口。

通过统一入口输入原文并上传图片、Excel（XLSX/XLS）、PDF、PowerPoint（PPTX/PPT）、JSON 或 UTF-8 CSV/TXT，不要求用户选择数据源或分析类型。保存后立即启动真实模型：先根据材料内容自动匹配需求拆解、问题分析或 VOC/BI 证据分析，再按唯一匹配路径完成分析。结果保留匹配类别、实际 Skill、理由、材料信号和置信度；类别与 Skill 不一致时运行失败，不静默降级。历史手动分类案例继续兼容。

原始附件保存在本机，文档在保存案例时解析，页面展示提取预览和警告。JSON 作为证据材料，不用于恢复运行历史，也不执行其中的指令。模型调用复用现有安全凭据运行档，支持已配置的公司或个人档；没有可用模型时明确失败，不生成假分析。附件单个最多 5 MB、合计最多 10 MB、最多 8 个；大数据应先拆分案例。

文档解析使用当前 Python，缺少依赖时尝试 Codex 本机 bundled Python。其他环境可运行 `python3 -m pip install -r requirements.txt`。旧版 XLS/PPT 需要本机 LibreOffice（soffice），转换在隔离临时目录中完成。不会修改原文件。PDF 扫描页、演示文稿中的图片与图表不进行 OCR/视觉解读，警告会随提取内容传给模型；纯扫描 PDF 会拒绝空文本解析，需另行上传截图。加密、损坏或超过解析限制的文件不会静默跳过或截断。

也可独立配置环境变量 `SKILL_AGENT_API_URL`（Chat Completions 完整地址）、`SKILL_AGENT_MODEL` 和 `LLM_API_KEY`。Key 应通过安全环境注入或终端隐藏输入，不写入源码、页面或命令历史。这些变量仅在没有可用已选运行档时作为独立配置使用，审计标记为 `standalone_environment`。

DeepSeek 官方接口使用 `tool_choice=auto` 保留思考模式，避免强制工具调用触发 HTTP 400；输出预算为 32768 token，单次请求超时 600 秒。其他接口保持原配置。大批量材料可能需要数分钟；结果截断或结构无效会标记失败，不自动采纳。审计记录工具选择方式、输出预算和超时。

自动匹配会读取仓库现有问题分析、需求拆解、VOC 与 BI Skill。界面将 VOC/BI 作为一条“证据分析”业务路径，内部仍根据材料选择 VOC 标签路由与反馈优化组合，或 BI 告警诊断，不合并其方法约束。需求定义和指标定义读取对应 Skill 及完整规范。上传的截图以图片内容传给模型；模型不支持视觉时运行失败，不悄悄忽略截图。无产品线目录时仅输出标注为非正式的建议归属。

这是实验工作台，组合 VOC 实验不等同于正式 N1/N2a 流程；需求池和后续定义只存在本地实验空间，不向外部需求平台发布，不自动执行正式 N3–N5 门禁。模型输出和人工评判分别留存，每次重跑保留独立版本。基线缺失必须显式记录，AI 目标建议不等同已确认 KPI。

案例列表和详情显示分析中、分析成功或分析失败。成功生成的粗需求直接持久化到左侧「需求池」，不再要求在案例页采纳或手动导入；零候选明确显示本次未生成粗需求，失败不入池。自动入池不是人工采纳，也不伪造评价记录；来源证据、匹配依据和历次分析保留。历史已驳回结果不自动恢复入池，重新运行按新结果处理。

左侧「需求池」承载尚未完成定义的粗需求；单条结构化定义成功后自动进入「需求分析」，评审、修订及指标定义在该板块处理。定义生成不等于已采纳，指标生成仍要求采纳对应定义。已有有效单条定义自动归类；定义失败或旧版整批结果不会导致需求误进入新板块。原始记录和历史运行不删除，分阶段列表由持久化记录计算，刷新和重启不丢失归属。

本次交付的自动化测试不等同真实模型端到端验收。真实运行需用户当前运行档可用，且图片案例需要所选模型/网关支持视觉输入。

## Tracking 模拟闭环

指标定义被人工采纳后，平台会幂等创建 Tracking 草稿，不再要求重新抄写需求和指标。草稿保留 `source_record_id → analysis_run_id → candidate_id / requirement_id → definition_run_id → metric_run_id → tracking_id` 链路；Skill 输出中的文字基线和目标只作为建议展示，平台不会猜测数值目标、样本量、观察窗口或责任人。独立 BI 告警仍可通过 `form.data` / `form.params` JSON 手工导入；当前 BI 示例一次接受一条建图成功率模拟指标，并要求 `is_simulation=true`。

处理流程：指标采纳或 BI 导入 → 人工核查与分配 → 冻结可计算目标、口径、最低样本和观察天数 → 记录模拟上线 → 定期拉取或手工补录观察 → 真实模型运行效果复盘 Skill → 人工选择达标关闭、继续迭代或继续观察。数值比较采用确定性计算；模型只解释原因、证据缺口和下一步，不能改测量值或人工决定。三种闭环决定都要求当前观察已有对应复盘；达标关闭还要求最新观察数值达标。

首版定期取数适配器支持平台内 JSON / CSV 模拟源以及手动、每日、每周计划。每条源记录须提供 `source_record_id`、`stat_date`、`attempt_count`、`success_count`、`window_days`、`version`、`definition`，可选 `note`。服务端按 `source_record_id` 保存游标并幂等跳过重复记录，保留每次拉取的触发方式、成功/失败、导入数和跳过数；整批校验失败不会部分写入观察结果。后台每 15 秒检查到期计划。本适配器不连接真实 BI 或修改外部业务系统，将来可在不改变后续状态机的前提下替换为正式接口适配器。

冻结标准有版本，上线后不能倒改；观察口径/版本不一致或样本/时间不足时为不可判定。闭环决定会回写关联需求：达标关闭标记原需求已闭环，继续观察标记为观察中，继续迭代则基于当前复盘 `next_action` 自动建立一条关联粗需求并保留原需求、Tracking、观测和复盘 ID。独立 BI 告警因没有需求链路仅记录跳过回流。数据保存在 SQLite 同目录 `tracking.json`；这是本地 Skill 验证闭环，不等同正式 N6/N9 Gate、生产上线或真实效果结论。
